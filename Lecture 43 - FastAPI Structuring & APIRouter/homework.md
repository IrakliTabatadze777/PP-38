# საშინაო დავალება: FastAPI Structuring

## საჭირო Entity-ები

პროექტში უნდა იყოს შემდეგი 6 Entity:

1. **User** — მომხმარებელი
2. **Product** — პროდუქტი
3. **Category** — კატეგორია
4. **SubCategory** — ქვეკატეგორია
5. **Order** — შეკვეთა
6. **OrderItem** — შეკვეთის ცალკეული პოზიცია (რომელი პროდუქტი, რა რაოდენობით შედის კონკრეტულ შეკვეთაში)


    ველები განსაზღვრეთ თქვენი სურვილისამებრ
---

## მოდელების ზოგადი აღწერა

ველების ზუსტი ჩამონათვალი და კავშირების დეტალები **განზრახ არაა მოცემული** — ეს თავად უნდა გაიაზროთ და დააპროექტოთ, სტანდარტული e-commerce ლოგიკიდან გამომდინარე. რამდენიმე მიმართულება, რაზეც უნდა იფიქროთ:

- **User** — მომხმარებლის საბაზისო ინფორმაცია
- **Product** — პროდუქტის საბაზისო ინფორმაცია - უკავშირდება ეს `Category`/`SubCategory`-ს.
- **Category / SubCategory** — უკავშირდება ერთმანეთს
- **Order** — უკავშირდება კონკრეტულ მომხმარებელს
- **OrderItem** — შეკვეთაში მოცემული პროდუქტები, უკავშირდება ერთდროულად `Order`-სა და `Product`-ს

## ფუნქციონალური მოთხოვნები

თითოეულ Entity-ს უნდა ჰქონდეს სრული CRUD:

| Endpoint | Method |
|---|---|
| `/{entity}/` | POST |
| `/{entity}/` | GET |
| `/{entity}/{id}` | GET |
| `/{entity}/{id}` | PUT |
| `/{entity}/{id}` | DELETE |

`Category`+`SubCategory` და `Order`+`OrderItem` წყვილებისთვის — თითოეულ Entity-ს **ცალკე** endpoint-ები სჭირდება

დამატებითი ლოგიკა სავალდებულო არაა და ცალკე არ შეფასდება.

## ტექნიკური მოთხოვნები

1. **Models** (`models/`) — მხოლოდ მონაცემთა ბაზის მოდელები.
2. **Schemas** (`schemas/`) — Pydantic მოდელები (`Create`, `Update`, `Read`) თითოეული Entity-სთვის.
3. **Repositories** (`repositories/`) — მხოლოდ მონაცემებთან პირდაპირი ურთიერთობა. **არანაირი ბიზნეს ლოგიკა.**
4. **Services** (`services/`) — ბიზნეს ლოგიკის ფენა, repository-ს გამოძახებით.
5. **Routers** (`routers/`) — მხოლოდ HTTP endpoint-ები, service-ის გამოძახებით.
6. **main.py** — ყველა router-ის დარეგისტრირება.
7. **core/database.py** — მონაცემთა ბაზასთან კავშირის კონფიგურაცია (ან in-memory storage, თუ DB არ გამოიყენება).
